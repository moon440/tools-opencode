## Context Mode large-file test

Input file:

```text
raw size:      138,326 bytes
lines:         2,000
estimated raw tokens: about 34,600 tokens
```

Context Mode returned only a derived JSON summary:

```text
returned bytes: about 164 bytes
raw bytes kept out of chat context: about 138,162
```

Result:

```json
{
  "rawBytes": 138326,
  "lines": 2000,
  "errors": 285,
  "total": 26013000
}
```

Cost effect if the file had been read directly into the active context:

```text
additional permanent cached context: about 34,600 tokens
additional cache-read cost per later request: about $0.00055
additional cost over 100 later requests:       about $0.055
additional cost over 1,000 later requests:     about $0.55
```

The direct-read version also makes the first later cache miss more expensive:

```text
34,600 additional uncached input tokens: about $0.0052 one-time
```

Conclusion: Context Mode is valuable when the raw source is large or repeated.
It is not free because its MCP schemas increase the fixed prefix, but those
schemas are cheap compared with repeatedly carrying raw file bytes.

## What caused the $0.11-$0.24 spikes

At a provider prefix around 783k-800k tokens:

```text
full uncached input cost: about $0.118-$0.120
plus normal output cost
```

A 24-cent request corresponds to a larger context and/or larger reasoning output
with no cache:

```text
context: about 1.2M equivalent uncached cost plus output/reasoning
```

These spikes happen when one of these changes:

```text
server restart
model switch
MCP connect/disconnect
plugin/config reload
tool schema mutation
instruction change
compaction
provider TTL expiry
```

The solution is not to make every miss cheaper by using a weaker model. The
solution is to keep misses rare and contexts small.


## Known risk that cannot be removed by OpenCode permissions

The shell tool runs as the logged-in Windows user. File permission rules reduce
agent mistakes, but they do not sandbox:

```text
child processes
PowerShell scripts
Python
Node
SQLite
archive extraction
file copying
network requests
```

For stronger protection, run OpenCode under a dedicated low-privilege Windows
user or in an isolated VM/container.
